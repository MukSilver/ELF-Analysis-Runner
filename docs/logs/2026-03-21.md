- validate_target()를 두어 경로 검증과 실제 분석 로직을 분리했다.
- analyze_target()와 print_analysis_result()를 분리해, 분석과 출력의 역할을 나눴다.

## 오늘 배운 것
- 기능이 조금씩 커질수록, 단순 print 위주보다 결과를 딕셔너리로 관리하는 구조가 훨씬 유리하다는 걸 배웠다.
- 경로 검증과 ELF 분석을 한 함수 안에 다 넣으면 나중에 수정이 어렵다는 걸 느꼈다.
- 출력용 함수와 실제 분석용 함수를 분리하면 재사용성이 좋아진다는 점을 배웠다.
- 프로젝트는 처음부터 “완벽한 기능”보다 “확장 가능한 구조”를 먼저 만드는 게 중요하다는 걸 느꼈다.

## 지금까지 만든 것
- make_result() 결과 템플릿
- validate_target() 경로 검증 함수
- print_analysis_result() 출력 함수 초안
- analyze_file() 중심 구조 초안

## 느낀 점
- ELF가 맞는지만 보면 될 줄 알았는데, 실제로 생각보다 더 판별할게 많았고, 어떻게 저장하고 확장할지도 처음부터 정해서 하는게 편하겠구나 느꼈다.
- 구조가 정리가 되니까, 확실히 더욱 툴(도구)처럼 보이기 시작했다.

## 막힌 점
- 함수 분리를 어디까지 해야 하는지 감이 애매했다.
- analyze_file() 안에 뭘 넣고, 출력은 어디서 해야 하는지 역할 구분이 헷갈렸다.
- 나중에 JSON 저장까지 하려면 지금 결과 구조를 어떻게 잡아야 할지 감이 완전히 잡히진 않았다.

## 해결한 점
- 분석 결과를 딕셔너리로 통일하면 출력, 저장, 비교가 쉬워진다는 방향을 잡았다.
- 입력 검증과 ELF 분석을 나눠서 생각하니 코드 흐름이 훨씬 단순해졌다.
- “지금 당장 안 쓰더라도 결과 키를 미리 만들어 두자”는 방향으로 정리하면서 이후 확장 준비를 했다.
